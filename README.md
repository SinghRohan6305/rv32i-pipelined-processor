# RV32I 5-Stage Pipelined Processor (VHDL)

A 5-stage RISC-V **RV32I** pipeline written in **VHDL-2008**, targeting an Intel
Cyclone V FPGA (`5CSEMA5F31C6`) with a 100 MHz timing constraint.
Verified in simulation by **28 self-checking testbenches**, from per-module unit
tests up to an end-to-end Fibonacci program.

## Microarchitecture

```
IF ──> ID ──> EX ──> MEM ──> WB
```

- **Full RV32I** — all 40 base instructions (R/I/S/B/U/J types; `FENCE`/`ECALL`/`EBREAK` retire as NOPs).
- **Hazard detection unit** — load-use hazards stall the front end for exactly 1 bubble.
- **2-stage forwarding** — `EX/MEM → EX` and `MEM/WB → EX` bypass paths remove ALU-to-ALU RAW stalls (a load followed by its use still costs 1 bubble).
- **Branch prediction** — 1-bit BHT, 16 entries, indexed by `PC[5:2]`. Looked up in ID; a predicted-taken branch redirects fetch from ID (1 bubble). The prediction travels with the branch and is checked in EX.
- **Branches and jumps resolve in EX** — 2-cycle misprediction/jump penalty; IF/ID and ID/EX are flushed.
- **Harvard memory** — separate synchronous IMEM (ROM) and DMEM (RAM). IMEM is addressed with the next PC so its registered output lines up with the PC; load data is consumed in WB, the cycle it arrives. DMEM is byte-addressable and handles sign/zero extension for all load widths.
- Control signals are bundled into VHDL records (`ctrl_ex_t`, `ctrl_mem_t`, `ctrl_wb_t`) so pipeline registers stay readable.

## Layout

```
src/
  pkg_riscv.vhd        Opcodes, ALU codes, shared constants, control record types
  alu.vhd              32-bit ALU
  regfile.vhd          32x32 register file (x0 hardwired to 0, write-through forwarding)
  branch_predictor.vhd 1-bit branch history table
  hazard_unit.vhd      Load-use stall logic + forwarding mux selects
  imem.vhd             Instruction memory, initializable from a hex file via generic
  dmem.vhd             Data memory with load/store size and extension handling
  control_unit.vhd     Instruction decode -> control bundles + immediate generation
  pipeline_top.vhd     Top level: pipeline registers and full integration

tb/                    28 self-checking testbenches (see below)
tools/gen_tests.py     Assembler + ISA reference model; generates the pipeline testbenches
tools/rvdis.py         RV32I disassembler for checking hex words
sim/run_all_nvc.sh     Runs the full suite with nvc and prints a PASS/FAIL summary
sim/run_all.do         Equivalent ModelSim script
synth/                 Quartus project (.qsf) and 100 MHz timing constraints (.sdc)
```

## Verification

| Level | Testbenches |
|---|---|
| **Unit** | `alu`, `regfile`, `imem`, `dmem`, `control_unit`, `hazard_unit`, `branch_predictor` |
| **Instruction coverage** | `r_type` (all 10), `i_type` (all 9), `all_loads` (all 5, with sign/zero extension), `all_stores` (all 3), `load_store`, `branch` (all 6 taken), `branch_not_taken`, `branch_loop`, `lui_auipc`, `jal_jalr`, `fence_system` |
| **Hazards & forwarding** | `hazard_raw`, `hazard_load_use`, `forwarding` (exhaustive 2-stage coverage), `store_forward`, `branch_with_forwarding`, `consecutive_branches`, `pipeline_stall_count` |
| **Edge cases** | `overflow_edge`, `reset` |
| **End-to-end** | `full_fibonacci` — runs a Fibonacci program on the pipeline and checks `fib(10) = 55` |

The 21 pipeline-level testbenches are generated by `tools/gen_tests.py` from RV32I
assembly. The script assembles each program, runs it on a Python instruction-set
model, and emits a testbench that checks the hardware's registers against
that model's results. `pipeline_stall_count` also checks exact bubble counts
(load-use = 1, jump = 2). Every testbench ends in a PASS/FAIL verdict and fails
the simulation on any mismatch.

Each testbench writes its program to a hex file during elaboration and passes it
to IMEM through the `INIT_FILE` generic, so no RISC-V toolchain is needed.

## Simulating

```bash
# nvc (free: brew install nvc / apt install nvc) — all 28 pass
sim/run_all_nvc.sh

# ModelSim / Questa (not yet run with this script)
cd sim && vsim -c -do run_all.do

# Regenerate the pipeline testbenches after editing a program
python3 tools/gen_tests.py
```

## Synthesizing

Open `synth/rv32i_pipeline.qsf` in Quartus Prime (Cyclone V,
`5CSEMA5F31C6`). `synth/rv32i_pipeline.sdc` constrains the clock to 100 MHz.

## Known limitations

- **Not yet synthesized.** ALM utilisation and Fmax require a Quartus run; whether 100 MHz closes is unknown.
- DMEM is a byte array read at four addresses at once, so Quartus will likely not infer M10K for it as written. Splitting it into four byte-lane banks would fix that.
- Load-use detection compares `rs2` even for instructions that have no `rs2` (I-type, loads), so it occasionally stalls when it doesn't need to.
